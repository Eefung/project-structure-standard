# 迁移清单

把 `docs/standard.md` 落到四个存量仓库。原则三条：

1. **一次一个仓库**：改完立刻跑该仓库 CI 与检查器，绿灯再动下一个。
2. **结构迁移独立提交**：挪文件、补许可证、改标题都单独成一次提交，别和内容修改混在一起，出问题能整段 revert。
3. **只重组，不重写**：README 改成六段结构时，原有内容按语义搬到对应节里，措辞不动；确实写不清的段落才重写。

完成判据：四个仓库跑 `scripts/check-layout.sh <仓库>` 全部退出码 0，且 CI 通过。

## 通用做法

```sh
# 1. 先看现状（贴成对照表，再动手）
grep -nE '^#{1,2} ' ~/Projects/<仓库>/README.md

# 2. 改完自查
~/Projects/project-structure-standard/scripts/check-layout.sh ~/Projects/<仓库>

# 3. 单独提交结构改动
git -C ~/Projects/<仓库> add README.md
git -C ~/Projects/<仓库> commit -m 'docs: README 按六段结构重排'
```

注意：`文档` 一节不是「文档内容」，是指向 `docs/` 的索引。原来塞在 README 里的长专题（原理、证据、排障）搬到 `docs/` 下，README 只留一行链接。

四个仓库的自述都是中文，所以标题用中文：`# 自然语言项目名`、`## 工作原理`、`## 安装`、`## 用法`、`## 文档`、`## 许可`。H1 除了从 slug 换成中文名，还要真的像一个名字——`tui-mode-recovery` → 「TUI 键盘恢复」、`obs-nvenc-legacy` → 「OBS NVENC 旧驱动修复」。
